# AMS2 Race Randomizer — starter build

## Что уже заложено
- Три голосуемые категории: трасса, класс автомобиля, погода.
- По одному выбору в каждой категории.
- Повторное голосование с тем же ником заменяет предыдущий голос.
- Админ-вход через Supabase Auth.
- Добавление и мягкое удаление вариантов.
- Открытие/закрытие голосования.
- Weighted-жеребьёвка в SQL-функции на стороне базы.
- Сохранение результата и базовая история.

## Бесплатный запуск
1. Создай проект на https://supabase.com.
2. Открой SQL Editor и выполни `schema.sql`.
3. В Authentication -> Users создай пользователя-администратора с email и паролем.
4. Скопируй UUID этого пользователя и выполни в SQL Editor:
   `insert into public.admin_users(user_id) values ('UUID');`
5. В Project Settings -> API скопируй Project URL и anon/public key.
6. В `app.js` замени `YOUR_SUPABASE_PROJECT_URL` и `YOUR_SUPABASE_ANON_KEY`.
7. Размести три файла (`index.html`, `app.js`, `schema.sql`) на статическом хостинге, например Cloudflare Pages или Netlify.

## Важные ограничения текущего starter build
- Участник идентифицируется ником. Это удобно, но не защищает от того, что человек проголосует повторно под другим ником. Для строгого контроля нужны приглашения/одноразовые коды или вход участников.
- Публичное чтение таблицы голосов в этой схеме подходит только для небольшой закрытой компании, где никого не смущает видимость записей. Для приватности лучше заменить это на серверную агрегацию голосов.
- Для настоящего production запуска стоит добавить проверку, что все выбранные option ID принадлежат разрешённым категориям, лимит длины и уникальность приглашений, а также создание следующего события из админки.
- Никогда не публикуй Supabase `service_role` key. В браузере допустим только anon/public key при включённых RLS.
